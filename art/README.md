# Art pipeline: Blender-built models

Every costume, item and piece of scenery in `public/assets/` is generated by
the Python scripts in `art/blender/`, run headless in Blender. The scripts
sculpt a detailed high-poly model, build a light game mesh, then bake the
detail into textures with Cycles on the GPU. The game ships only the light
meshes and the baked textures, so the extra detail costs almost nothing at
runtime. It stays playable on base Apple silicon Macs.

The game never depends on these files. If an asset is missing, fails to load,
or the player picks **Models → Classic** on the title screen (or adds
`?classic` to the URL), it uses the procedural models in `public/js/three/`.

## Build

You need Blender 4.2 or newer (5.x recommended). Any GPU that Cycles supports
speeds up the baking; the CPU works, but more slowly.

```powershell
.\art\build.ps1                          # everything (~25 min on an RTX 4090)
.\art\build.ps1 -Only trex,egg -Preview  # some assets, plus review renders
.\art\build.ps1 -Only scenery            # a whole group: costumes, props, scenery
```

```bash
./art/build.sh --only trex --preview     # macOS / Linux
```

The build finds Blender on `PATH`, through the Microsoft Store alias, or at
`C:\Program Files\Blender Foundation`. Set `BLENDER` to override it. The log goes to
`art/.cache/build.log`. `-Preview` writes Cycles renders of the finished game
meshes to `art/.cache/previews/`, with PNG copies of every texture in
`previews/tex/`. The cache folder is ignored by git.

Each build updates `public/assets/manifest.json`. The game reads the manifest
at start-up to find the files.

## What gets built

| Group | Assets | Game mesh | Textures |
|---|---|---|---|
| `costumes` | trex, raptor, trike, stego, ptera, ankylo, parasaur, pachy | 20–24k triangles, rigged, 6 materials | fabric masks + normal (1024²), trim colour/ORM/normal (512²) |
| `props` | egg, nest, bomb, peel, tar, meteor, bone_hurdle, log_hurdle, arch, blaster, mallet, balloon, hatchling | 0.15–2.5k triangles | colour/ORM/normal (+ glow) |
| `scenery` | palm, jungle_tree, fern, boulder, flower, spire, dead_tree, rib, vertebra, skull, floodlight | 0.1–4k triangles (mostly instanced) | colour/ORM/normal (+ glow) |

## Costumes

`art/blender/costumes.py` builds each costume in the following steps.

1. **Body shell.** The same spine curve and cross-section profile as the
   procedural model, swept at 240×144. It is displaced with sewn panel seams,
   pillowing between the seams, pull creases, and compression folds at the
   throat and tail root.
2. **Head and limbs.** These are sculpted with metaballs (implicit surfaces),
   so the parts blend like stuffed fabric. The eyes are ray-cast onto the head.
   Arms sit on the upper chest beside the bib.
3. **Details.** Glossy eyes with printed irises, blinking fabric lids, felt
   teeth along the lip line, trousers with bunched folds and gathered cuffs,
   running shoes with a treaded outsole and laces, the blower fan, the face
   window and the bib.
4. **Species extras.** Spikes, feathers, stuffed plates with piping,
   armour scutes, a frill, crests, wings and a tail club. Anything that would
   poke through the face window is left out.
5. **Game mesh.** The low-poly shell has hand-made UVs, split along the
   dorsal and belly seams. The other parts are decimated and smart-UV'd, then
   everything is packed into one atlas per material.
6. **Bakes (Cycles, GPU).** Ambient occlusion is baked onto the high-poly
   vertices first. It is then baked with the colour masks and normals onto the
   atlas.

### The rig contract

`public/js/three/dino3d.js` drives these bones by name:

| Bone | Parent | Animation |
|---|---|---|
| `pivot` | — | trips and falls |
| `torso` | pivot | bob, lean, roll, inflation wobble, deflation sag |
| `spine_0 … spine_N` | torso (the pelvis bone), then chained outwards | tail sway, neck bob |
| `head`, `jaw` | last spine bone, head | head turn, jaw (taunt, overheat) |
| `lid_0`, `lid_1` | head | blinking (modelled open) |
| `arm_0`, `arm_1` (`wing_0`, `wing_1`) | a spine bone | arm swing, flapping |
| `hip_i`, `knee_i`, `ankle_i` | pivot | running |
| `fan` | a spine bone | the blower spins |

Index 0 is the runner's side at −x. Every bone points straight up in Blender
with zero roll, so it exports to glTF with an identity rotation. The game can
then set joint angles exactly as it does for the procedural costume.

### Materials the game maps

| glTF material | Game material |
|---|---|
| `fabric`, `membrane` | nylon (sheen, clearcoat). The **mask** texture is R = dark markings, G = belly, B = accent, A = occlusion; the shader colours it with the runner's palette, so one texture set serves every colour |
| `trim` | teeth, eyes, horns, shoes, fan. ORM = occlusion, roughness, and (B) where the runner's sneaker colour goes |
| `face`, `bib` | canvas textures drawn by the game per runner |
| `window` | the clear PVC dome |

No texture keeps data under a zero alpha, because browsers may premultiply
alpha while decoding.

## Items, props and scenery

`art/blender/props.py` and `art/blender/scenery.py` use `lib/static.py`. Each
asset is a list of high-poly parts, and each part names the game mesh it
belongs to. A palm, for example, has a `trunk` and `fronds`, and only the
fronds sway in the wind. Every asset is modelled at the size and origin that
`props.js` and `scenery.js` already place it with. Meshes the game tints per
instance (canopies, ferns, flower petals, mystery eggs) are baked near-white
so the tint shows through.

## Performance notes

Measured in three.js on the High preset, with six runners on the grid and the
shadow pass included:

| | Classic (procedural) | HD (Blender) |
|---|---|---|
| One costume | 39–53 draw calls (22–34 cast shadows), 29–38k triangles | 5 draw calls (2 cast shadows), 20–25k triangles |
| Stadium scene | 148 calls, 611k triangles | 110 calls, 624k triangles |
| Jungle scene | 143 calls, 780k triangles | 104 calls, 770k triangles |
| Volcano scene | 116 calls, 213k triangles | 85 calls, 244k triangles |

- A costume draws in about 6 calls: fabric, trim, face, window and bib, all on
  one skinned mesh per material. The procedural costume needed about 40.
- Skinned costumes cull against a fixed sphere that holds any pose, so
  runners behind the camera or outside the shadow frustum cost nothing.
- Instanced scenery keeps each instance close to the procedural shape's
  triangle count (for example, a fern is 112 triangles; 1,100 are drawn). The
  leaves are folded blades whose leaflets come from the baked textures, with
  no alpha testing, which is costly on the tile-based GPUs in Apple silicon.
- Triangle budgets are set per part (`tris=`) and printed in the build log.
- Textures are WebP and meshes use `EXT_meshopt_compression`, decoded by
  three.js' bundled meshopt decoder. A costume downloads as about 1.3 MB.
- The title turntable and the thumbnails use their own copies of the
  textures. The thumbnail renderer is released after a few idle seconds, so
  the GPU memory isn't held during the race.
